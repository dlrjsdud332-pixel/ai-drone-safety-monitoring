## 사용자 검수 데이터 — 미완료

다운로드 폴더에서 확인한 것은 저장된 검수 **HTML 페이지**다. 사용자 수정 박스/완료 상태가 들어 있는 검수 JSON은 아직 찾지 못했다. 저장된 페이지의 화면 문구는 `8/30 사용자 완료`였지만, HTML은 실행 중 JavaScript의 편집 상태를 보관한 파일이 아니다. 이 화면 문구를 8개 또는 30개 정답 승인 근거로 사용하지 않았다.

실제 원래 검수 탭이 열려 있다면 새로고침하지 말고 **작업 전체 JSON 다운로드**를 사용해야 한다. HTML을 다시 열면 기존 작업이 복원된다고 보장할 수 없다. 결과 JSON을 확보할 때까지 라벨 반영·기준 정확도 측정은 진행하지 않는다.

| 구분 | 사용자 승인 확인 | 정답 기준 미탐지율/오탐률 |
|---|---:|---|
| 밝은 낮 | 미확인 | 미측정 |
| 석양 | 미확인 | 미측정 |
| 야간 | 미확인 | 미측정 |

로컬 데이터셋에는 기존 미검수 30프레임이 그대로 있으며 사용자 승인 라벨은 0개다. 이전의 2/13 결과는 부분 영역 진단값으로, 현재 30프레임 전체의 기준 정확도가 아니다. 실제 화재 누락과 비화재 오탐의 정답 기준 확인은 JSON 검증 후 진행해야 한다. 자동 예측 박스 수를 정확도로 표시하지 않는다.

## 환경 제한과 미검증

- AI 환경에는 `gz.msgs10`이 없어 Gazebo 전체 테스트 첫 시도는 모듈 import 오류였다. 기존 전용 Pixi Python으로 다시 실행해 16건이 통과했다. pip 환경에 Gazebo 패키지를 임의 설치하지 않았다.
- 현재 X500 실제 Image 토픽 검사를 5초 제한으로 실행했으나 `X500 Image topic not discovered`로 실패했다. QGroundControl의 UDP 14550 프로세스는 보였지만 PX4 비행/텔레메트리 연결을 입증하지 않는다. 중복 서버를 새로 띄우거나 비행 명령을 보내지 않았다.
- 이번 세션의 실제 macOS Qt 화면, QGC 연결/자율비행/착륙, 카메라 영상, 미션 진행률 표시 재검증은 미완료다. 기존 사용자 성공 보고와 과거 offscreen 결과를 이번 실행 성공으로 바꾸어 적지 않는다.
- 새 Python 환경의 pip 설치, 누락 모델 설치, 최종 사용자 머신에서의 실행도 미검증이다.

산업현장 잔여 항목:

- `test_originals_unchanged`: `tools/gazebo/x500_camera.sdf`의 과거 baseline 해시와 현재 정상 카메라 이동 모델 해시가 달라 assertion 실패.
- `test_stages_preserve_flight_and_have_one_worker`: 현재 월드에서 옛 `model://x500_mono_cam` include를 찾는 `next(...)`가 `StopIteration` 오류. 산업현장 단계 월드와 현재 정상 X500 기준의 불일치가 남아 있다.
- 통과시키기 위해 원본 비행/카메라 설정이나 검사 기대값을 임의 변경하지 않았다. 산업현장 테스트는 Git 제외 진단 baseline에도 의존하므로 공개 소스만으로는 동일 재현이 보장되지 않는다.

군중 밀집·화재 전처리·HSV ROI·고해상도/타일 사람 검출은 모두 실험 기능이며 운영 미적용이다. 부분 영역 추가 검출은 정확도 인증이 아니다. 화재 30프레임은 사용자 완료 JSON 미확보로 정식 평가 미완료다. 실제 GUI·자율비행·QGC·미션 진행률·카메라 통합은 기존 사용자 성공 보고와 별개로 이번 준비에서 재실행하지 않았다. 새 환경 설치 및 전체 배포 라이선스도 미완료다.
